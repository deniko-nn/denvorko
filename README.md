# denvorko — сайт-портфолио веб-разработчика

React 19 + TypeScript + Vite. Страницы собираются в статический HTML (vite-react-ssg), поэтому поисковики видят весь текст и разметку, а React «оживляет» страницу в браузере.

## Команды
```bash
npm install        # один раз
npm run dev        # разработка: http://localhost:5173
npm run build      # сборка в папку dist (со статическими страницами, sitemap и robots)
npm run typecheck  # проверка типов
```

## Структура
- `src/pages` — страницы (Home, Services, Work, About, Contact, NotFound).
- `src/components` — HUD-шапка и меню, первый экран со слайдами и каркасной моделью, глитч-переходы, подвал, CTA, FAQ, макеты проектов, SEO-компонент.
- `src/data` — тексты и данные: услуги, кейсы, FAQ, Schema.org, контакты. Правьте здесь. Проекты (`cases.ts`): у каждого своя страница `/work/<id>`; обложки лежат в `public/assets/projects/<id>.svg`.
- `src/styles/global.css` — дизайн-система в стиле «иммерсивный HUD» (токены цветов, отступов, шрифтов в начале файла). Сайт тёмный, переключения тем нет.
- `src/animations` — место для анимаций (см. README внутри).
- `site.config.json` — адрес сайта, почта, Telegram, GitHub.
- `public` — картинки, манифест. Файл `public/CNAME` с доменом включает режим своего домена.

## Публикация (GitHub Pages)
Один раз: **Settings → Pages → Source: GitHub Actions**. Дальше каждый пуш в `main` собирает и публикует сайт (`.github/workflows/deploy.yml`).

## Что заменить перед запуском
1. Адрес сайта в `site.config.json` (сейчас адрес GitHub Pages). С своим доменом: поменять `url`, добавить `public/CNAME`.
2. Почта и Telegram в `site.config.json` (сейчас заглушки).
3. Кейсы (`src/data/cases.ts`), сроки и условия (`src/data/services.ts`), опыт и навыки (`src/pages/About.tsx`).
4. Подключить Яндекс Метрику и Search Console, отправить `sitemap.xml`.

## Патч vite-react-ssg
Папка `patches/` содержит правку библиотеки (применяется автоматически после `npm install` через `patch-package`): при ошибке загрузки служебного JSON сайт не падает, а продолжает работать. Без неё пользователь с закэшированной старой версией после нового деплоя видел «Unexpected Application Error».

## Безопасность и скорость
- **Политика безопасности (CSP).** GitHub Pages не позволяет задавать HTTP-заголовки, поэтому при сборке (`scripts/postbuild.mjs`) в каждую страницу добавляется мета-тег Content-Security-Policy: скрипты только с этого сайта и встроенные по хэшу, никаких внешних ресурсов. Если добавляете счётчик Метрики или другой внешний скрипт, разрешите его домен в `scripts/postbuild.mjs`.
- **Шрифты свои** (Fontsource): без запросов к Google, быстрее и приватнее.
- **Код делится на части:** главная грузится отдельно от остальных страниц, карусель, WebGL-фон и возможности Framer Motion подгружаются после первой отрисовки.
- **Экономия:** тяжёлый WebGL-фон не загружается при включённой экономии трафика и на очень слабых устройствах.
- **Форма:** длина полей ограничена, из темы и заголовков письма убираются переводы строк и управляющие символы.
- **Зависимости:** Dependabot раз в неделю предлагает обновления, а при публикации `npm audit` останавливает сборку при серьёзных (high и выше) уязвимостях.
- **Известное замечание аудита:** две уязвимости средней тяжести в `react-router` 6 (открытый редирект в `Link` с данными от пользователя и подмена ошибок при гидратации). Исправления для ветки 6 нет, а `vite-react-ssg` требует именно её. На сайте все ссылки статические, а вставка стороннего кода в страницу блокируется политикой CSP, поэтому риск практически нулевой. Следите за обновлением `vite-react-ssg`.
- **Защита от встраивания** (clickjacking) на GitHub Pages возможна только скриптом в шапке: заголовок `frame-ancestors` недоступен. Для полной защиты используйте Cloudflare или другой хостинг с настройкой заголовков.

## Проверка безопасности (Strix)

[Strix](https://github.com/usestrix/strix) — ИИ-агент, который сканирует код и находит уязвимости. Сканируйте только свои проекты.

```bash
uv tool install strix-agent        # или: pipx install strix-agent
export STRIX_LLM="openrouter/z-ai/glm-5.3"
export LLM_API_KEY="ключ-провайдера"
strix -n -t ./ --scan-mode quick   # нужен запущенный Docker; отчёт в strix_runs/
```

В GitHub: добавьте секреты `STRIX_LLM` и `LLM_API_KEY`, затем Actions → *Strix security scan* → Run workflow.
